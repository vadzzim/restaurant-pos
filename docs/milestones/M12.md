# M12 — The failure simulator

§18's eleven controls, each with visible feedback, on `/debug`. Model **Sonnet**, size **M**.

Most of the switches already exist and almost none has a button; this milestone is mostly wiring,
plus a write surface, plus the four controls that have no mechanism at all.

## The one decision to make first: the write surface

`/debug` has been read-only since M11 and §17 lists exactly one write endpoint,
`POST /api/debug/flags/:key`, which is M13's. Inventing five endpoints is the failure mode here,
so M12 adds **one pair**, shaped like the one M13 will add:

- `GET  /api/debug/simulator` — the state of the server-side switches.
- `POST /api/debug/simulator/:control` — flip one. Returns the new state, so a button needs no
  second round trip to know what it did.

Four controls go through it: `outbox-pause`, `outbox-delay`, `printer-fail`, `replay-last-event`.
Everything else in §18 is a client-side switch and needs no endpoint at all. Record the decision
as **ADR 015**.

### `Replay Last Kafka Event`

The API has no Kafka producer and must not grow one for a demo button. Instead reset the newest
published, non-dead-lettered `outbox_events` row back to claimable — `published_at = null`,
`claimed_by`/`claim_until`/`last_error` cleared, `next_attempt_at = now()`. The publisher claims it
within one `OUTBOX_POLL_MS` and sends it again; both consumers deduplicate it through
`processed_events`. That is §19.6 exactly, driven by machinery that already exists.

Two honest consequences to state on the page and in `known-problems.md`: the published count drops
by one while the row is back in flight, and a replayed row is *earlier* than any unpublished event
for the same aggregate, so it briefly holds them behind it (the claim query's per-order ordering).

### `Force Polling Transport`

M13 owns the polling transport. Here the latch makes this terminal take the **existing
`PUSH DISABLED` branch** — no socket, screens still correct after every mutation, no live updates —
without touching the fleet-wide flag. It differs from `Disconnect WebSocket`, which drops a socket
that push still wants and will reopen. Label it plainly: today it is the disabled branch, M13 makes
it a working second transport. Do not build polling here.

## Where the code goes

- `packages/db` — **move** `readOutboxControls` / `setOutboxControls` out of the worker into
  `packages/db/src/outbox-controls.ts`, beside `printer-controls.ts` and for the same reason: both
  ends need it and neither owns it. `watchOutboxControls` stays in the worker; it is the
  publisher's polling loop, not a shared fact.
- `packages/contracts` — `SimulatorState`, `SimulatorControl`, the POST bodies, the replay result.
- `apps/api/src/modules/debug/` — `api/simulator-routes.ts` and `application/replay-last-event.ts`.
  Register in `app.ts` beside `registerDebugRoutes`.
- `apps/web/src/api/simulator-arms.ts` — the three one-shots and the two latches, as plain module
  state with an effect log. `postMutationTo` consults it: it rewrites `baseVersion` before the
  send, and fires the shadow send after. The shadow's response is logged, never returned.
- `apps/web/src/stores/simulator.ts` — the server state, the POSTs, and the client arms re-exposed.
  `stores/debug.ts` stays read-only.
- `apps/web/src/components/SimulatorPanel.vue` — replaces the *Not on this page yet* article in
  `DebugView.vue`. Keep the feature-flag line; that one is still M13's.

## Traps

- **The one-shots fire on another screen.** `/debug` is its own route, so the operator arms a
  control here and walks to `/pos/pos-1`. Module state survives the route change; it does **not**
  cross tabs. Say so on the panel and in `known-problems.md`.
- **`Create Version Conflict` cannot fire on a `CREATE_ORDER`** at `baseVersion` 0. Keep it armed
  until it meets a mutation with `baseVersion ≥ 1` rather than silently spending itself.
- **A pause is observed within one `OUTBOX_POLL_MS`**, and `outbox_controls` is fleet-wide. Both
  are already in `known-problems.md`. A button that implies instant, per-worker control is worse
  than no button.
- **The POS header toggle must keep working.** It reads the same `offline.ts` state; do not fork it.
- **Do not fix the M11 review backlog.** Three entries, swept in a dedicated pass.
