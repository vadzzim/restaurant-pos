# M26 — Portfolio presentation and recorded demo

## Goal

Make the repository's relevance legible in under two minutes and provide a reproducible,
narration-free proof of the hardest implemented flows.

## In scope

- Reorder the README opening around concrete engineering problems and their source/ADR evidence.
- Put the correct CI badge and an implemented-components Mermaid diagram near the top.
- Add a dedicated Playwright recording flow and `pnpm demo:record` without changing normal E2E.
- Publish a compact captioned H.264 MP4 covering realtime KDS delivery, offline drain, an
  optimistic conflict with Rebase, and outbox pause/recovery without adding it to Git history.
- Document exact regeneration and MP4 publishing.

## Out of scope

Application redesign, mocked demo behavior, a repository media dependency, automatic transcoding,
new CI infrastructure, and claims about unimplemented production extensions.

## Files

`README.md`, `e2e/demo.spec.ts`, `playwright.config.ts`, `scripts/verify-e2e.mjs`, the root script,
`docs/demo.md`, the hosted MP4 attachment, and recorder output under `.verify-output`.

## Key decisions

- The demo uses the production bundle and the same real Compose/API/worker lifecycle as E2E.
- Captions are injected into the recorded browser viewport so the asset needs no narration.
- Simulator state that is tab-local crosses routes through Vue Router, not a full navigation.
- H.264 MP4 is the public artifact for browser compatibility; Playwright's WebM remains a local,
  reproducible source rather than a versioned binary.

## Verification

`pnpm demo:record`, `pnpm test:e2e`, `pnpm verify:multi`, lint, typecheck, 507 tests, integration
round trips, and production builds. Check the video's duration/size, local Markdown targets,
Mermaid rendering, `git diff --check`, and absence of scratch recordings.

## Definition of done

The README communicates the system, difficult guarantees, demo path, and architecture immediately;
the final video shows all four real scenarios in about one minute; regeneration is one command;
normal CI/E2E selection is unchanged; and no temporary media or unsupported capability is committed.
