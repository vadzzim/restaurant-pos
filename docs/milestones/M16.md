# M16 — Guided demo

`/demo` walks an interviewer through all ten §19 scenarios: what to do, in order, and what to watch
while doing it. Today it is still the M1 `PlaceholderView`.

**Verification: each scenario can be performed by following the instructions, with no
improvisation.** That is the whole bar. If a step says "press X" and no X exists, the milestone
failed. If a step needs a fact the page never gave (which tab, which terminal, which counter), it
failed.

## Scope

1. `src/domain/demo-script.ts` — the ten scenarios **as data**, plus the pure functions over them.
   Same reason as `pos-screen.ts` and `debug-view.ts`: content that only exists inside a template
   is content no test can check. A scenario is `{ id, spec, title, claim, setup[], steps[] }`;
   a step is `{ do, watch?, control?, route? }`.
2. `src/views/DemoView.vue` — a scenario picker, the selected scenario's steps, and **one**
   `<SimulatorPanel />` at the foot. Steps name a control and link to it by anchor; they do not
   re-render it. (ADR 015's split is real: a tab-local arm pressed here survives the SPA walk to a
   POS screen, a hard reload loses it. The page must say so.)
3. `SimulatorPanel.vue` gains an `id` per control so those anchors resolve.
4. `router.ts`: `/demo` → `DemoView`.
5. **P1-in-M12 fix, in scope because §19.3's single-tab path names it** — `Create Version Conflict`:
   - it waits for `baseVersion >= 1`, so at v1 it sends v0, which `mutation-routes.ts` refuses with
     `min(1)` as *invalid*, not conflicting. Guard must be `>= 2`.
   - `spend()` runs only after `postMutationTo` returns, so that 400 leaves the arm armed and
     tampers every later mutation from the tab. Spend on an `ApiRequestError` too — the server
     answered — but never on `OfflineError` or a dead network, which is what the guard is for.
6. `test/demo-script.test.ts`.

Out of scope: the seventeen-entry backlog; PWA; Playwright; changing `onBeforeUnmount`'s
`orders.clear()` (see below).

## Decisions to make deliberately

- **§19.10 is already a passing test** (`pnpm verify:multi`, M14). Its scenario entry says so and
  gives the command. Do not stage a fake two-instance walk in the browser.
- **Walking off a POS screen clears its order** (M8 `onBeforeUnmount`). So a step must never say
  "go back to /demo and then continue with the same order". Either the step keeps the operator on
  the POS screen, or it opens `/demo` in a second tab. **The script routes around it; the code does
  not change** — changing it is an M8 behaviour with its own blast radius, not a demo feature.
- Multi-terminal scenarios (§19.3, §19.8) need **two tabs**, and the offline switch is tab-local,
  so the script must say which tab presses what.

## The ten, in one line each

1. Normal flow — POS-1 → Burger, Cola → Send to kitchen → `/kitchen` New → Start preparing → Mark
   ready → POS follows → Pay card.
2. Offline — arm `Simulate POS-1 Offline`, create a **new** order, add two items, change a
   quantity, watch 4 pending, go online, watch it drain to zero.
3. Conflict with a blocked queue — two tabs, POS-1 offline queues three, POS-2 cancels, POS-1 back
   online: 409 then two `BLOCKED`; Discard or Rebase; `/debug` conflict history.
4. Duplicate mutation — `Duplicate Next Mutation`, then one tap; `duplicateMutationsPrevented` +1,
   the line does not double.
5. Reused mutationId — `Reuse Mutation Id With New Payload`; `mutationIdReuseRejected` +1.
6. Duplicate Kafka event — `Replay Last Kafka Event`; `duplicateKafkaEventsPrevented` +1, the
   kitchen projection does not move.
7. Outbox publication failure — `Pause Outbox Publisher`, send to kitchen, `outboxEventsPending`
   climbs and the ticket never appears; resume, it appears. The order was never lost.
8. Two kitchen displays race — `/kitchen` in two tabs, both press `Mark ready`: one applies, one
   conflicts.
9. Printer down — `Fail Printer`, send to kitchen, watch the print job retry then `DEAD_LETTER`;
   `Fix Printer`, press `Retry`. The order was never affected.
10. Multi-instance broadcast — `pnpm verify:multi`, quoted as the test it is.
