# M23 — The cached client

The third pass of *The second sweep* (`MILESTONES.md`). Five backlog lines, and unlike M21 and M22
they share a **surface** rather than a mechanism: the browser. Three live in `src/sw/` + `src/pwa/`,
two in the two screens that a demo is actually walked on.

A milestone here is finished when its five lines are **gone** from `known-problems.md` — deleted if
fixed, moved up into *Accepted limits* if the honest answer is that the behaviour is right.

## The five

1. **`[M17, P2]`** — the only P2 left in the file. `activate` deletes every cache that is not this
   build's, while a page still running the *old* bundle has been claimed by the new worker. Harmless
   today only because `router.ts` imports all four views statically; ADR 017 names code splitting as
   the condition to revisit, so read the ADR before touching `sw/`.
2. **`[M17, P3]`** — a failed precache fails the whole installation: `install` waits on a document
   fetch that throws, the worker never activates, and the next load has no shell at all.
3. **`[M17, P3]`** — the update path force-reloads the tab on `controllerchange` with no prompt. The
   queue is on disk, but a half-typed cover name in the POS header is not.
4. **`[M16, P3]`** — no UI path puts a second terminal on an existing order, so §19.3's literal
   two-terminal form needs `curl`. `focusOrder` exists in the order store and is wired only to
   "Go to it" on a stranded halt.
5. **`[M16, P3]`** — `/demo`'s step ticks are in memory, so a reload mid-demo loses the place.

## The shape of the fix

**1 and 3 are one argument, not two.** Retaining the previous build's cache is what makes *not*
reloading safe, and prompting instead of reloading is what makes retaining it necessary — a page
that keeps running the old bundle for as long as the operator wants must be able to fetch that
bundle's chunks. So: `activate` keeps **two generations** (`__SW_BUILD__` is `Date.now()`, so the
names sort), an `asset` miss in this build's cache falls back to `caches.match` across all of them,
and `controllerchange` raises a **banner** rather than calling `location.reload()`.

**2** makes `install` best-effort end to end, which needs somewhere to recover: the first navigation
that reaches the network re-runs the asset precache, once. Without that, an install that failed
leaves a worker whose runtime caching never sees the bundle (the page fetched it before the worker
existed) — the exact hole ADR 017 opened the precache to close.

**4** is an order-id field beside the cover pad, calling the `focusOrder` that already exists.

**5** puts the ticks in the query string, where `?scenario=` already lives and for the same reason
`DemoView.vue` already argues: it survives a reload, the Back button, and being handed to somebody.
Switching scenario still drops them, so a second walk-through does not start half done.

## Constraints

- ADR 017's rules hold: nothing in `src/sw/` imports from the rest of `src/`, the worker owns the
  shell and never data, and the allow-list stays an allow-list. If retaining a generation changes
  what the ADR claims, **amend the ADR** — do not leave it contradicting the code.
- `apps/web` has no component-test harness (no `@vue/test-utils`). Logic that needs a falsifying
  test goes into `src/domain/` or a store; `.vue` files stay rendering.
- Each fix needs a test that **fails without it** — the M21/M22 standard. Suites:
  `test/service-worker.test.ts`, `test/cache-policy.test.ts`, `test/demo-script.test.ts`,
  `test/order-store-behaviour.test.ts`.
- Two existing service-worker tests assert the behaviour being deliberately changed
  (*"drops every cache that is not this build"*, *"fails the installation when the document itself
  cannot be fetched"*). Rewrite them; do not add a second test beside a stale one.

```
pnpm lint && pnpm typecheck && pnpm build

```

Then the browser half, which no unit test reaches:

- `pnpm -F @pos/web build && pnpm -F @pos/web preview` — install the worker, add a dynamic
  `import()` to one view, rebuild, reload **offline**, and check the old page still resolves its
  chunk. (Revert the `import()`; it is a probe, not a change.)
- Open `/pos/pos-1`, note the order id, then from `/pos/pos-2` open it by id — §19.3 without `curl`.
- Tick three steps on `/demo`, press F5, and find them still ticked; switch scenario and find them
  gone.
