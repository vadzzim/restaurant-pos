# M25 — Prometheus observability

## Goal

Add the smallest credible production-debugging surface that reflects real system state without
turning this repository into monitoring infrastructure.

## In scope

- `GET /metrics` on the API using an established Prometheus client.
- Bounded-label HTTP duration/count, mutation outcomes, and WebSocket connections.
- Outbox backlog/dead letters, oldest unpublished age, and print states read from PostgreSQL only
  when Prometheus scrapes.
- One integration test, a concise metric catalogue, and a few actionable alert examples.

## Out of scope

Prometheus or Grafana deployment, dashboards, distributed tracing, Kafka lag export, consumer-side
dead-letter topics, and high-cardinality order/tenant labels.

## Files

`apps/api/src/modules/observability/`, the common API response and mutation boundaries,
`apps/api/test/metrics.test.ts`, `docs/observability.md`, `ops/prometheus/alerts.yml`, and the
dependency lockfile. Architecture/spec wording must stop describing Prometheus as wholly absent.

## Key decisions

- Process counters are module-local and each API replica is scraped separately.
- Durable gauges use one shared aggregate PostgreSQL query per scrape; normal requests run none.
- HTTP labels use the matched Fastify route pattern, never a raw URL or business identifier.
- Alert only on operator-actionable durable states: old outbox work and dead letters.

## Verification

`pnpm format`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm verify:integration`,
`pnpm test:e2e`, `pnpm verify:multi`, and production image builds. The metrics test must prove the
route label contains no UUID and the database-backed gauges reflect inserted rows.

## Definition of done

The endpoint exposes six useful metric families, labels are bounded, database work happens only on
scrape, tests cover the consistency outcomes and delivery gauges, alert names match real exported
metrics, and documentation distinguishes implementation from future observability work.
