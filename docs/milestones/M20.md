# M20 — Backlog sweep

Not a feature milestone. `CLAUDE.md`'s *Review discipline* promised a dedicated pass every three or
four milestones, and it was deferred at every one of them: `known-problems.md` carries **thirty**
P2/P3 entries, none ever swept. This is that pass, and it is the whole session.

## Scope

Thirteen entries, chosen because each is either a real defect or a one-line correction, and because
the three `PROGRESS.md` named as the strongest candidates are all in the set. Everything else in the
backlog stays, with the reason it stayed written next to it.

**Structural (four):**

1. **[M15, P2]** Same-millisecond queue order. `savePending` stamps `createdAt` to the millisecond
   and the queue sorts by it with a random-UUID tiebreak, so two taps in one millisecond can send
   `baseVersion` 4 before 3 and halt on a race the operator never caused.
2. **[M15, P2]** The storage-less `settle()` path runs outside the serialized chain, so on a device
   whose IndexedDB refuses writes, rapid taps attempt concurrently at the same `baseVersion`.
3. **[M16, P2]** `conflict_log.resolution` is only ever written `null`, so `/debug`'s
   **Conflict history** can never show a resolved row and `unresolved` only ever grows.
4. **[M11, P2]** `readDatabaseCounters` runs three times per `/debug` poll — eleven `count(*)`
   scans every two seconds against unbounded tables.

**Corrections (nine):**

5. **[M11, P2]** The kitchen heartbeat reports `pendingCount: 0` unconditionally, and the comment
   claiming the kitchen has no queue is wrong.
6. **[M12, P3]** `replayLastEvent` does not reset `attempt_count`, so a replay can dead-letter early.
7. **[M12, P3]** `busy` in the simulator store holds one control name, so overlapping presses leave
   a button enabled while its request is out.
8. **[M11, P3]** A presence `terminalId` is validated as 1–64 characters, not against `TERMINALS`.
9. **[M11, P3]** `claimed` tracks only the socket's latest terminal, so an earlier claim outlives
   the disconnect.
10. **[M15, P3]** `commit()` in `PosView.vue` has no `catch`.
11. **[M15, P3]** `engine.rebase` carries the same six-line comment twice.
12. **[M18, P3]** `getByText('WS CONNECTED')` matches by substring.
13. **[M18, P3]** `API_READY_URL` hard-codes `localhost:3000`, ignoring `API_PORT`.

**Two entries are already fixed** and are deleted rather than swept: both M15 `P1-in-M12` lines —
`applyVersionConflictArm` has its `LOWEST_TAMPERABLE_VERSION` guard and `postMutation` spends the
arm on an `ApiRequestError`. The backlog outlived the fix.

## Out of scope, and why

- **[M17, P2]** SW cache eviction — ADR 017 names code splitting as the condition to revisit; the
  router still imports all four views statically.
- **[M19, P3]** Mark-then-emit ordering — §12.2 is explicit about the order; changing it trades a
  loss window for a duplicate window, which is an ADR, not a sweep.
- **[M15, P2 monotonic-sequence wording]** closed by entry 1 without the schema change it proposed.
- Everything else: still one line each in `known-problems.md`.
